# Proposal: Import Real Data from Game Screenshots

## Why
The project currently relies solely on synthetically generated training data (skill icons with overlaid text). While this approach provides a controlled dataset, it may not fully capture the visual characteristics and variations found in real game screenshots. By importing actual game screenshots from the `real_data/` directory, we can:

1. **Improve model robustness**: Real data includes authentic lighting, anti-aliasing, compression artifacts, and rendering variations that synthetic data may not replicate
2. **Increase training diversity**: Combining synthetic and real data provides a more comprehensive training set
3. **Validate model performance**: Real data serves as a better proxy for actual deployment conditions
4. **Leverage existing data**: The `real_data/` directory already contains labeled screenshots that should not go unused

The automated import process ensures consistent organization and random distribution, maintaining dataset quality while scaling efficiently.

## Summary
Import real game screenshot images from `real_data/` directory and distribute them into the training dataset structure based on filename labels. This adds real-world data to supplement the synthetic data generated by the existing data generation system.

## Background
Currently, the project generates synthetic training data using skill icons as backgrounds with overlaid text. However, we now have access to real game screenshots captured directly from the game interface. These real images can improve model accuracy by providing authentic samples.

The `real_data/` directory contains PNG files with filenames following the pattern: `valid_<label>_<timestamp>.png`, where:
- The first segment (after splitting by underscore) must be "valid" or "Valid"
- The second segment is the character label (0-9, A-Z single characters, or the special label "NA")
- The third segment is a timestamp

**Update (2026-01-06)**: Added support for "NA" label to capture game screenshots where the label represents a specific character class or category in the game interface.

## Goals
1. Parse filenames from `real_data/` to extract labels
2. Validate filename format and filter valid images
3. Randomly distribute images into train/val/test directories with 75%/15%/10% split
4. Copy images to appropriate label subdirectories under `data/{train,val,test}/`
5. Provide logging and statistics for the import process

## Non-Goals
- Modifying existing data generation code
- Image preprocessing or augmentation
- Changing the directory structure of `data/`
- Training model with imported data (separate task)

## Affected Components
- New capability: **data-import** - handles importing real game screenshots
- Existing `data/` directory structure - receives new images

## User Impact
- Developers can run a script to import real data
- Training dataset will include both synthetic and real images
- Model should achieve better accuracy with real-world samples

## Risks
- Filename parsing errors if format is inconsistent
- Insufficient data for certain labels
- Random split might not be truly random if run multiple times (mitigated by optional random seed)

**Resolved**: Previously identified risk about "NA" label handling has been addressed by explicitly supporting it as a valid label.

## Alternatives Considered
1. **Manual copying** - Too error-prone and time-consuming
2. **100% deterministic split** - Less flexible, harder to re-balance
3. **Fixed ratio per label** - More complex, unnecessary for initial implementation

## Success Criteria
- All valid images from `real_data/` are copied to correct label directories
- Split ratio is approximately 75%/15%/10% for each label
- Script provides clear logging and statistics
- No data loss or corruption during copy
