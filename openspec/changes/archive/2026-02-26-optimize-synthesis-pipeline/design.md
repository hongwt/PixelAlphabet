## Context

当前合成管线基于早期 Java 版 AutoGenImage 的逻辑直接移植，采用在背景上直接绘制文字的简单方案。
文档《基于Python底层图像处理库的像素级定制化合成管线设计》提出了严格的 4 层架构来提升合成数据的物理真实度。
用户提供的真实图片样例（技能图标 + 白底黑边字符）是优化的目标参照。

## Goals / Non-Goals

**Goals:**
- 实现文档所述 4 层合成管线（前景渲染→背景采样→Alpha合成→退化增强）
- 生成的合成数据应在视觉特征上更接近用户提供的实际游戏 UI 图片
- 保持 CLI 向后兼容，新功能通过可选参数控制

**Non-Goals:**
- 不引入像素字体资产（当前仍使用现有字体库，像素字体可后续迭代引入）
- 不实现课程学习或 Focal Loss 等训练阶段优化（属于训练管线范畴）
- 不实现 GAN-based 风格对齐（属于高级管线，后续迭代考虑）

## Decisions

### Decision 1: 使用 Pillow 原生 stroke API 替代 8 方向偏移
- **原因**: Pillow ≥ 6.2.0 原生支持 `stroke_width` / `stroke_fill`，像素完美且无偏移伪影
- **替代方案**: 继续使用 8 方向偏移但修复对齐 → 弃选，因为原生 API 更精确且代码更简洁

### Decision 2: 前景/背景分离的 RGBA Alpha 合成
- **原因**: 文档强调"硬覆盖"操作是模拟 HUD 渲染 BitBLT 的核心。分离渲染允许精确控制 Alpha 通道实现非此即彼的覆盖语义。
- **实现**: 
  1. 前景层：RGBA 透明画布，`fill=(255,255,255,255)`，`stroke_fill=(0,0,0,255)`
  2. 背景层：从图标/截图裁剪的 RGB 图块
  3. 合成：`Image.alpha_composite()` 或手动逐像素硬覆盖

### Decision 3: 所有空间变换使用 NEAREST 插值
- **原因**: 文档数学分析表明，像素化游戏 UI 的渲染是绝对二值化的，BICUBIC/LANCZOS 插值会引入平滑过渡像素，破坏离散高频梯度特征
- **范围**: `resize_image`、退化管线中的 downsample/upsample

### Decision 4: 退化操作以概率随机组合应用
- **原因**: 真实截图的退化是非确定性的，随机组合能覆盖更多真实情况
- **实现**: 每个退化操作有独立的启用概率（默认 0.3-0.5），可通过 degradation 强度参数统一缩放
- **库选择**: 使用 NumPy 进行数值操作，PIL 进行 IO，不引入 OpenCV 依赖（保持轻量）

## Risks / Trade-offs

- **风险**: 退化增强可能过度破坏字符特征 → 通过限制退化参数范围和可调强度缓解
- **权衡**: 不引入 OpenCV 意味着部分操作需用 NumPy 手工实现 → 可接受，因为操作简单且减少依赖
- **权衡**: 初版不引入像素字体 → 当前字体库仍可产出合理的训练数据，像素字体作为后续优化
